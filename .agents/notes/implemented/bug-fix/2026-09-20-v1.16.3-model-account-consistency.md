# Agent Note: v1.16.3 模型目录与停用账号语义收口

Status: implemented

## Problem

v1.16.2 把 `freebucks.prices` 纳入 Web 模型管理后，暴露出几处不同层级之间的语义
不一致：

1. `/api/accounts/refresh` 第一阶段会跳过 `enabled:false`，但末尾调用
   `probeAllAccountsSession()` 刷新模型目录时又遍历全部账号，可能重新创建停用账号
   runtime 并主动 GET 上游，违反“停用账号不参与任何后台批量探测”的约束。
2. 价格表独有模型能出现在 `/api/models/upstream`，但 `modelIdsFromSession()`
   只看当前 model / rate limits / offers，导致 Web 看得到、`/v1/models` 和未知模型
   白名单却可能仍拒绝。
3. “同步上游模型”按钮调用普通缓存接口，60 秒内可能拿旧目录，名字叫同步但没有强制 fresh。
4. 多账号 fresh 只合并 `rateLimitsByModel`，`freebucks.prices` 仍继承第一个成功账号，
   无法表达账号池价格表并集。
5. v1.16.2 将价格表独有模型同步为 `pool='freebucks'`。旧 `isFreeModel()` 只把
   `premium` 视作付费，于是 `freebucks` 会错误进入“免费模型”的提前 re-admit /
   更激进分散策略；但 Freebucks 每次 admit 都按会话计费，应优先复用热 session。

## Decision

- `probeAllAccountsSession()` 只遍历启用账号，并在进入 runtime 前再次
  `runtimes.isEnabled(key)` 双检；全部停用时清空目录缓存，不访问任何账号。
- 多账号 fresh 同时合并两本账：
  - `rateLimitsByModel` 取并集；
  - `freebucks.prices` 取并集。
  若同一模型跨账号价格不同，记录 warning 并保守取较高价。
- `modelIdsFromSession()` 把有限数值的 `freebucks.prices` key 纳入统一模型 id
  集合，使价格表独有模型进入 `/v1/models` 与未知模型白名单。
- Web “同步上游模型”改调 `/api/models/upstream?fresh=1`；fresh 路径强制执行
  多账号探测，普通模型管理页仍保留 60 秒缓存。
- Proxy 主链路不再只把单个 `getAny()` 当完整目录：每次模型探测先合并共享
  `runtimes.list()` 中所有启用账号已经缓存的 quota/freebucks/model，再只做一次
  `getAny()` 实时 GET。这样 Web fresh 后 `/v1/models` 和 chat 白名单立即吸收
  多账号并集，又避免每次 /v1/models 对所有账号制造一轮网络探测。
- `isFreeModel()` 把 `freebucks` 与 `premium` 都视为“非免费会话调度”：
  `premium` 仍可由 blockPremium 屏蔽；`freebucks` 可调用，但采用付费会话热复用/
  较晚 re-admit 策略。

## Alternatives considered

- **只修 Web UI，不动 proxy 主链路** — 会继续出现“控制台看得到但 /v1/models /
  chat 不认识”，因此否决。
- **Proxy 每 60 秒并发探测所有启用账号** — 目录最完整，但账号多时会形成明显的周期性
  批量 GET，既增加延迟也增加不必要的上游行为特征；改为“共享 runtime 本地并集 +
  单账号实时 GET”。
- **价格冲突保留第一个账号值** — 隐式依赖账号顺序且可能低估某些账号实际扣费；采用
  较高价更保守，并打 warning 便于发现上游灰度差异。
- **继续把 freebucks 当免费 pool，仅靠 paid window 防止释放** — re-admit lead 和
  调度分类仍会错误，可能在接近过期时提前买新会话；因此必须从模型分类入口修正。
- **让普通 /api/models/upstream 永远 fresh** — 模型管理首屏会重新变慢并增加上游
  探测；只有显式“同步”动作才强制 fresh。

## Consequences

- 手工停用账号不会因“一键刷新”末尾的模型目录阶段重新触达上游。
- 仅存在于 `freebucks.prices` 的模型在 Web、`/api/models`、`/v1/models`
  和 chat 白名单中的发现口径一致。
- 多账号 fresh 可以看到所有启用账号的价格模型并集；价格冲突以较高价展示。
- “同步上游模型”立即反映最新上游目录，不受 60 秒缓存影响。
- `pool=freebucks` 的模型继续可调用，但调度更偏向复用已购买会话，降低重复 admit
  导致的额外 Freebucks 消耗。
- 默认设置和现有 `premium` 屏蔽语义不变。

## Testing

`test/smoke.mjs` 新增/补强：

- `modelIdsFromSession()` 包含价格表独有模型，忽略非法价格；
- `pool=freebucks` 的自定义模型由 `isFreeModel()` 判为 false；
- `modelListOnlyFreebucks` 非布尔值返回 400，布尔值可持久化往返；
- disabled 账号执行 `/api/accounts/refresh` 后 runtime 仍未被重建；
- 双账号不同 `freebucks.prices` fresh 后取并集；
- 同模型价格冲突取较高值；
- 普通接口命中缓存，而 `fresh=1` 能看到缓存后新增模型；
- Web fresh 后 `/v1/models` 立即包含多账号价格表模型并集。
