# Agent Note: 账号出口绑定改成真下拉，不再要求手输代理 URL

Status: implemented

## Problem

「账号出口绑定」弹窗里，专属代理是一个 `<input list="…">` + `<datalist>`：

- 候选项本来就是**代理池里固定的那几个出口**（`/api/proxy` 返回的 `proxies`），
  但 datalist 只在**开始敲字之后**才给建议，点开下拉什么也看不到 →
  实际用起来就是「把选择做成了填空」。
- 每次绑定都要从代理设置页复制一段 `http://user:pass@host:port` 再粘贴；手输
  打错一个字符的后果不是"回落到池里其它出口"，而是**硬绑定到一个连不上的出口**
  （PATCH `proxy` 的语义就是"专属单代理、失败不再切池"）。
- 已绑定的账号再打开这个弹窗时，输入框只显示一段需要原样保留的字符串——
  误改/清空即等于悄悄解绑或改绑。

## Decision

弹窗内的专属代理改成真正的 `<select>`：

- 选项来源统一复用 `collectAvailableProxies()`：控制台代理池 + config/env 实际生效出口
  + 现有账号绑定/当前出口 + 上一轮成功缓存；避免实际正走环境代理时这里却误报"代理池为空"。
- 选项：`不绑定（使用全局池；故障时可能切换出口）` / 每个可用出口（当前生效的那个
  额外标 `· 当前生效`）/ **已绑定但不在当前集合中的代理**（池被改过或历史手工绑定的，
  单独给一项，防止"打开→保存"把绑定静默改掉）/ `自定义…（手工输入代理 URL）`。
- 只有选中 `自定义…` 时才显示文本框（`#account-proxy-input` 默认 `display:none`），
  常规路径完全不用打字；如果账号已有专属绑定，自定义框会预填当前 URL，便于只改局部。
- 保存时取 `select.value`；选中自定义且文本框为空 → **拒绝提交**并提示，
  不再把"没填完"当成"取消绑定"（旧代码 `input.value.trim()` 为空即提交解绑）。
- 值不在候选项里（异常数据）时回落到"不绑定"，避免下拉显示第一项却提交另一个值。

## Alternatives considered

- **保留 `input + datalist`**：就是被否掉的现状。datalist 的交互在多数浏览器里
  既不显示候选也不支持键盘选择，等于没有下拉。
- **只做下拉、去掉自定义输入**：池为空（或需要池外代理）时该功能直接不可用，
  而 `/api/proxy` 允许池为空，这个组合是真实存在的。
- **用 radio 列表铺开所有出口**：出口多时把弹窗撑满，且与「新账号」弹窗已有的
  下拉交互不一致。

## Consequences

- 常规绑定路径从"复制粘贴"变成两次点击；打错 URL 的风险只剩显式的自定义路径。
- 已绑定池外代理的账号打开弹窗不会丢绑定（新增的"不在池中"选项）。
- 自定义路径多一道非空校验：提交空值会收到提示而不是静默解绑。
- `#account-proxy-input` 仍在 DOM 中但默认隐藏——依赖它做自动化/测试的地方
  需要先选 `自定义…` 再填值。

## Testing

- `npm test`：除 dashboard 语法门禁外，新增源码级回归断言，钉死统一出口集合、
  池外绑定保留、自定义预填、空自定义拒绝提交。
- `npm run typecheck`、`verify-all.ts --base HEAD`。
- 真实页面验证（隔离实例 + 用 `web-sessions.json` 里的会话 cookie 注入浏览器）：
  弹窗打开后 `<select>` 直接展示可用出口，默认选中当前生效出口，
  选择 `自定义…` 才出现文本框。
